# 本机标定与素材边界

真实窗口模式依赖本机配置，而不是下载仓库就自动获得游戏识别能力。整个准备过程应保持 `ready_for_input: false`。

## 1. 选择坐标基准

`frame_size` 为程序使用的标准图像宽高，示例为 371 × 709。驱动截取整个目标窗口外框，并缩放到该标准尺寸；不是桌面整屏，也不是仅截游戏棋盘。离线检查图须采用同样裁剪边界与缩放方式，否则检测坐标没有可比性。

`window_title` 是目标窗口的完整标题。用 `desktop_app.py --locate-only` 检查定位；多个同名窗口、窗口比例不匹配或身份变化会阻止执行。切换版本、窗口装饰、DPI 或皮肤后，应重新检查配置。

`board_roi`、`tray_roi` 使用 `[左, 上, 右, 下]`，右、下边界不包含在区域内。两者必须处于标准图像内且不重叠。只把牌面区和槽位区纳入对应 ROI，不要包含按钮、奖励弹窗或其他应用。

## 2. 准备图案模板

仅使用本人有权使用的本地图片，不要复制他人的素材包。公开仓库没有游戏图案；测试中的噪声块由程序生成，不是游戏模板。

- 从标准尺寸图像中裁出清晰、无遮挡、未变暗的图案中心，避免大片背景和邻牌。
- 每个类别使用一个英文文件名，如 `kind_a.png`；同类的不同样本可用 `kind_a__v2.png`。双下划线前的部分是类别标识。
- 使用 1–128 个 PNG 文件，每个不超过 2 MiB；过小、纯色或超过棋盘区域尺寸的模板会被拒绝。
- 棋盘识别按模板原尺寸进行；槽位识别由 `tray_scales` 控制相对缩放。它不是整幅窗口的 DPI 参数。
- `minimum_score` 与 `maximum_mae` 分别限制模板相似度与平均绝对颜色差。数值较宽松会增加误检，不能把“检测数量更多”当作精度更高。

配置中只允许七格槽位、三张消除。不要通过修改规则字段把该原型当作任意消除游戏的通用执行器。

## 3. 离线检查

将经授权的截图保存在 `local/frame.png`，尺寸必须与 `frame_size` 一致：

```powershell
python desktop_app.py --self-check
python inspect_frame.py --image local/frame.png --output local/inspection-1
```

输出目录必须是新目录。检查其中：

- `annotated.png`：可见牌框与 UNKNOWN 区域是否符合实际。
- `state.json`：每张牌类别、槽位顺序与数量是否正确，隐藏信息是否仍标记未知。
- `decision.json`：当前决策是否选择确实可点击的牌；`pause` 表示信息或策略不足，不应靠放宽阈值强行消除暂停。

至少检查空槽、已有 1/2 张同类牌、多个类别混合、遮挡、动画结束、未知图案和窗口缩放等场景；不要只用裁模板的同一张截图验证。若图案未识别或槽位不完整，先补模板、修正 ROI 或缩放，再重复离线检查。

## 4. 允许一次真实操作

离线核对后，把本机配置的 `ready_for_input` 改为 `true`，先保留 `--max-steps 1` 和关闭探索。这个字段是用户确认，不是自动精度认证。

程序会激活窗口、移动光标并点击；不要同时操作鼠标。执行后检查会话前后截图与摘要。如结果不确定，程序不会自行补点；应人工检查现状后开启新的会话，不能直接重放旧坐标。

## 隐私与公开边界

`local/`、`standalone_sessions/`、演示输出、缓存及打包产物在 Git 忽略规则内。忽略规则不能阻止人为强制添加，也不能清除已提交文件，因此公开前仍需检查最终差异。

真实截图可能包含账号、窗口标题、个人内容或内部路径。不要提交这些文件；也不要把运行日志、标定素材包、游戏本体或第三方图案添加到仓库。若需要展示，只用可再分发且已脱敏的图像，并单独审核元数据。
